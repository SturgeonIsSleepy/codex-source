## 工作原则

以用户能正常播放和完成操作为验收依据，不靠编译成功代替功能验证。先记录现有能力与依赖，再逐块替换；不一次性删除大量代码。保留 MIT 及字体许可。项目之外的 Android Cloud 工具和其他条目保持稳定。

## 阶段与可复核交付

1. **补齐基线验收**：真实文件导入、播放/暂停/拖动、换曲、后台进度、音频焦点与耳机路由、通知返回、横竖屏；保存实际结果及截图，明确复现步骤。优先解决尚未通过的流程。
2. **抽出核心边界**：列出 Media3/Rust、MediaSession、音乐源协议、曲库/下载、队列、歌词等依赖，建立小接口和单一状态模型，逐步剥离上游 UI/导航耦合；删除前证明无必要调用，保留完整功能。
3. **重做使用流程**：自主规划首页、搜索、曲库、播放、歌单、下载和设置的信息架构。为导入、空状态、失败重试和音乐源配置提供清晰路径；在线能力缺少模块时如实说明。检查默认本地歌曲的分享/下载行为，避免无效的在线 ID 链接。
4. **全面统一视觉**：纸白、蓝天、手绘墨线、协调且笔画不偏细的中日文；在保留可访问性与触控热区的前提下使用图像资源。重构导航与组件，避免只把原版换色。
5. **角色与性能**：播放闭眼、暂停睁眼、随实际音乐自然连续摇摆；固定头/帽/发/手关系与共同底图。脸和右手不得白线或肤色拼接；不用多张整脸图切换。按需使用图像生成修复，核对原图，不盲目重绘。处理缓存、生命周期与实时线程成本。
6. **整理交付**：构建并检验 R8 release；合理包体、签名与 ABI，更新使用说明、变更、证据、已知问题和下一步。源码提交到本仓库，APK/JNI/日志归档进入相应 GitHub Release。

## 每次自动运行

拉取当前提交并检查现有更改，读取交接和最近验证。按优先级挑选真实可交付的一组任务，更新本计划并实施，完成适当验证后及时 commit/push。完成一个小阶段后继续下一有价值阶段；不人为空转。在运行时限、限额、权限/工具硬阻塞或用户暂停时保存状态、具体提交、未完成项和恢复步骤。不得把缺少验收、超时或人工终止写成测试通过。
