# ePlayer 0.6.3

本轮用户明确要求完整检查，覆盖新播放器、弹出队列、封面角色比例、统一按钮高度、更多菜单、长按多选、搜索键盘、设置层级、详情进出和底栏，以及基础导入/播放/暂停/切歌/引擎与音质、歌词、来源协议、缓存和音效。设备验收使用既有 TravelTest36，保留数据与签名，不操作实机或自动写入真实账号。

播放器不再是包含队列的长滚动列表。主界面固定封面/角色、元数据、同高操作胶囊、进度与五键控制；向上手势或底部入口打开独立 ModalBottomSheet 队列，角色随弹层隐藏。封面与人物重新使用同一 865×1280 场景坐标，杜绝大方形照片与另行缩小人物的比例分离。队列普通行右侧为更多，可收藏到歌单/移除；拖动仍通过整行长按，不再常驻移动条。

详情导航的闪烁根因是每个页面键包住 Dialog，推入/退出均销毁窗口。现保留同一 Dialog，只对内部内容分场景键，独立保留滚动。设置路径同样保留窗口，补充短入场位移。底栏去除单独的选中胶囊，统一图标、文字基线与相邻播放条。

基线 0.6.2 截图已在模拟器复现旧比例与连续长队列。主 agent 完成代码和测试；Terra high 只执行现有命令与设备操作。验收结果和最终包来源将在完整检查完成后补充。

首轮 c812f9f 的全 JVM 与构建成功，六项新 UI 回归实际执行：五项通过，长按第二项后选中状态失败。原因是内层 SongRow 点击仍在松手时运行，将长按选中的项取消；改为整行统一 combinedClickable，内层只绘制，避免子点击与长按重复处理。本轮未将该失败候选作为稳定交付。

首轮其余 22 类设备回归 57 项：53 通过、4 失败。三项是旧导航/旧文案断言，已按实际账号入口、定时状态更新；另一项为旧播放器横屏大字体滚动超时。将布局检查改为当前真实 YtmPlayerPanel，补充横屏左右分区：左侧角色，右侧可滚动的控件，避免大字体时操作不可达。将在最终候选重跑全部范围，不以改断言替代真实功能验收。

视觉复核还发现基线播放器的明亮取色使次要文字/未选中图标对比不足。增加受控底色遮罩，加入纯白封面下的实际渲染对比度检查，不仅校验静态配色。

最终生产代码候选 5f8c54b 的全 JVM 为 52/52，通过当前用户设备回归 58 项，另 6 项因保护既有队列主动跳过（总数 64）。临时 Android 用户补测 4/6 通过，涉及真实窗口的 AutoEQ/通知场景失败，已恢复 Owner 并移除临时用户；继续用独立干净 AVD 补齐，不将跳过或环境失败计为通过。测试脚本另外修正 AutoEQ 旧导航路径，通知测试使用真实通知点击而非受系统限制的后台 PendingIntent.send；未修改生产业务代码。

R8 稳定截图复核发现 ModalBottomSheet 根 modifier 上的 fillMaxHeight(.88) 使窗口缩短，队列底部露出原控制区。高度改到内容 Column，保持全屏弹层窗口并向底部锚定；补充实际屏幕底边断言和“第二首更多→添加到歌单/移除选中项”回归，未将中间动画帧或错误菜单路径视为验收通过。
