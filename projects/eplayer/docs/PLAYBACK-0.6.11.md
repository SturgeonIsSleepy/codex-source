# ePlayer 0.6.11

音源对同一请求音质可能返回不同码率、格式的文件。旧实现先按 cp URI 查缓存，再解析实际音频 URL，导致不同文件的字节范围拼接，出现固定位置跳段。

- 先解析实际文件，使用音源内容标识、大小、码率、格式、实际音质和试听范围组成独立缓存键。没有可靠内容标识时使用完整 URL。旧键不再命中，由原有 LRU 容量限制自然回收。
- 同一个提取器重开字节范围时禁止改变文件；发生变化后重建失败的媒体周期并按原时间定位，保留队列。
- CDN 返回 401/403/410 时最多刷新一次；仅相同文件继续读取。链接有效期遵循音源 expi，提前 15 秒更新，最高一小时。
- 音源临时 5xx 失败只进行一次短延迟重试；服务中的恢复每曲最多一次，用户暂停或切歌会取消。鉴权、会员权限错误不会反复重试。
- ExoPlayer 使用 WAKE_MODE_LOCAL，只在播放/缓冲请求期间持有 CPU 唤醒，暂停、结束、错误时释放。没有新增后台轮询或独立常驻锁。
- 本地文件与导入内容仍绕过流媒体缓存；完整缓存仍可在同一进程内离线读取。错误恢复由服务处理，不依赖前台界面。

验证：11 项定向 JVM 检查和 3 项模拟器缓存组件检查通过，包括同曲请求音质不变但实际文件变化、旧提取器拒绝拼接和新文件完整读取。实机 R8 通用包覆盖安装后，目标歌曲从 35 秒连续播放到约 55 秒，再回退重播到约 51 秒，未出现播放错误。对新版实际缓存进行独立 FLAC 解码：前 56 秒完整，35–51 秒重新定位后的 PCM 与首次解码一致。另一首目标歌曲息屏 75 秒仍保持播放，亮屏后无错误；队列 17 项保持，播放中的 CPU 唤醒已确认，暂停后释放。未测量功耗，未做整夜后台验证。

公开内容不包含手机原始日志、歌曲音频、账号、封面截图、代理节点或签名私钥。不计算 SHA256 或生成校验文件。
