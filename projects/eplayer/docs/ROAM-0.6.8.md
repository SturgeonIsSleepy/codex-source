# 0.6.8 实机漫游修复

## 已确认的问题与修复

- 手机 VPN 不允许绕过，0.6.7 默认直连在 socket 绑定处被系统以 EPERM 拒绝。经用户逐项授权，仅将 ePlayer 自用版加入 v2rayNG 分应用绕行名单并重连；其他应用的分应用选择保持原样。音频恢复 PLAYING 且无错误。
- 用户另行授权测试现有另一个节点，并提供新订阅。只从新订阅导入一个节点，未批量导入全部条目。可用节点的匿名歌曲搜索返回20条、Radio50条。不把令牌、节点连接参数、手机标识或账号写入本仓库。
- 同一有效代理上，应用原先的简写浏览器请求头返回空歌曲目录，完整浏览器标识返回正常目录。统一 WEB_REMIX 请求头，启动页只读128KiB前缀以获取客户端信息；JSON仍限制2MB，不下载整页后才丢弃。
- 网易云《一世風靡》与YTM《一世風靡 - SWAY》因双语标题被拒绝；另有 Suisei Hoshimachi / Hoshimachi Suisei 和 feat. 署名差异。依据元数据识别跨文字系统的双语标题、已知合作歌手署名和两词拉丁姓名顺序，补充譜/谱映射。现场、翻唱、混音、其他分段和英文版本仍受版本约束，不使用仅同名兜底。
- 显式重试清除旧出口的客户端/搜索缓存；地区受限、种子未找到和网易云匹配失败给出不同提示，播放器内使用短暂错误通知，不增加常驻说明标签。
- 已是物理默认网络时避免冗余 socket 绑定；必须绑定而不被允许时尽早给出可理解的路由错误，避免反复尝试全部地址。阶段诊断只记录数量、HTTP状态和异常类型，不记录标题、URL、凭据或账号。

## 验证与交付边界

38项定向JVM检查通过，其中1项是本地临时的真实公开响应检查（先复现失败，再修复通过）；可复用的37项用例不依赖私有响应文件。实际手机上核对了正常播放、YTM后端未变、搜索20条、Radio候选31条、两次补入5+3首，队列从9增至17，媒体会话开始播放新增项且error=null。不是仅用渲染器数量当作全链路成功。

用户随后要求立即结束，最终交付已在手机实测的 fastRelease 自用通用包（非debuggable），原签名、原NCM1.1.0与三ABI保留；没有追加最终R8压缩、全量回归或功耗测量。APK在源码最终提交前由同一工作树构建，内嵌GIT_SHA仍是上一基础提交，包记录明确这一点，不冒充提交后重建。

没有新增后台服务或定时重试；并发、别名补查和缓存边界保持原样。未自动切换网易云推荐。按用户要求不做SHA256校验或生成SUMS。真实截图、响应与实机日志不公开上传，订阅临时文件和代理端口转发在收尾时清理。
